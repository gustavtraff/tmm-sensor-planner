# Approved local v2 in-memory codec (#15/D)

On 2026-10-27 the owner explicitly approved the exact local TMMD v2 frame and TMMR
fingerprint format in [LOCAL_V2_FORMAT_PROPOSAL.md](LOCAL_V2_FORMAT_PROPOSAL.md),
including the independent test material from merged PR #102. Approval is recorded
in the conversation, not inferred from merging a proposal. This implementation
encodes/decodes bytes in memory and computes fingerprints only. There is no file
store/writer, migration, v2 activation, apply/consent API, reset, Android or transport.
Current DraftStore, TmmDraft domain version, InboxStore and outgoing formats remain
unchanged. No existing production caller is switched to v2.

## Values and API

- `LocalV2.State.neverSeen(uid)`, `.deleted(uid, version)` and `.active(version,
  draft)` describe one supplied local state. Versions are positive except never-seen
  absence, which fixes version 0. Never-seen states are accepted for fingerprints
  and before-decision state but cannot be persisted as slots. A historical before
  state contains metadata and the observed revision, with imageRef null; it is not
  a fresh/current complete local draft.
- `LocalV2.Snapshot(storeId, slots, decisions)` owns immutable copies of its ordered
  lists. Its decisions retain the typed action/outcome, receipt provenance,
  metadata, explicit counters/mask/time and reviewed fingerprint. Fingerprint
  arrays are copied at construction and returned by copy. TmmDraft values are
  already immutable; the codec never mutates input state or byte arrays.
- `LocalV2Codec.encode(snapshot)` validates the whole model and returns one complete
  frame with checksum. Metadata-only incoming/result carriers require revision 1
  and no imageRef; the active before-state carrier retains beforeRevision but
  rejects a raw imageRef. This avoids silently discarding client-local fields.
  Current active slots keep the full draft including its image association.
- `LocalV2Codec.decode(bytes)` accepts only a complete valid TMMD v2 frame. It rejects
  v1, unknown versions, corrupted/trailing/truncated input and inconsistent domain,
  slot, history, transition, provenance and recomputable-fingerprint data. It returns
  an immutable snapshot after full validation, without fallback, migration or partial
  results. It snapshots bounded input before checksum/decoding; callers must not
  mutate supplied arrays/collections concurrently with the call.
- `LocalStateFingerprint.digest(storeId, state)` returns a new 32-byte canonical
  TMMR format 1 SHA-256 digest. Numeric zero is normalized; text, nanoseconds,
  optional image association, counters and identities remain distinct. Supply the
  actual complete reviewed local state: a metadata-only historical state cannot
  reconstruct an old image association, and no digest proves image bytes/consent.

Structural null arguments are programmer errors (NullPointerException); invalid
factory versions/fingerprint length give fixed IllegalArgumentException messages.
Codec validation/size failures are IOException with the fixed message
`Invalid or unsupported local v2 data`, without input values or causes. The same
safe failure applies to fingerprint text/encoding limits. Callers must not log
models, raw metadata, image references or snapshot bytes on failure.

## Bounds and unchanged contracts

The codec checks independent 1,000-slot and 1,000-decision caps, plus the 16 MiB
complete frame cap and 65,536-byte strict UTF-8 string cap/domain limits. Output is
bounded as bytes are emitted, before an oversized output buffer can accumulate;
input size is checked before cloning/decoding. Counts and text lengths are checked
before iteration/allocation. Existing TMMI combined-entry limits are not reused.
Long.MAX_VALUE is valid stored counter evidence; transitions that would overflow
are rejected. There is no generation advancement, lock or filesystem I/O here.

The independent v1 expected-result fixture is decoded/re-encoded, not generated by
a migrator. Current DraftStore still writes version 1 and rejects v2; its code and
fixed v1 fixture are untouched. Reading approved v2 bytes cannot reconstruct older
v1 deletion/decision/variant/image history or imply a migration was committed.
Historical active fingerprints can only be recomputed where the required current
image association is still available under the approved rule; older rows keep
opaque 32-byte binding evidence rather than an invented historical image handle.

## Verification — 2026-10-27

`JAVA_HOME=<Temurin 17.0.20.1+1> sh scripts/test.sh` passed on macOS with
`javac --release 8` and assertions enabled, using only synthetic fixtures/temp data.

- The independent test-only Java inspector stays separate from production. All
  decoded slots/decisions/metadata fields, signed-zero bits, identities, counters,
  image references and fingerprints agree; production re-encoding matches each
  independent v2 frame exactly. All 18 Python-encoded preimage/digest vectors match
  production fingerprints. Fixture bytes and both old storage contracts are unchanged.
- Both readers reject the existing re-sealed malformed frame/domain/history corpus;
  production rejection preserves input bytes and uses fixed safe errors. Tests add
  invalid model history, contradictory provenance, leaked historical/incoming image
  handles and noncanonical metadata counters, with immutable list/array ownership.
- The independent caps accept 1,000 slots **and** 1,000 decisions together and reject
  the next entry. UTF-8 accepts 65,536 ASCII bytes or 32,768 two-byte characters and
  rejects an extra character/malformed surrogate, including image associations.
  Tests accept exactly 16,777,216 frame bytes and reject the next encoded/input byte.
- Existing core, inbox/review, v1 storage/reopen, outgoing metadata/preparation,
  four-type offline envelope checker and 100-device scenarios also pass. These are
  checks of unchanged contracts, not changes to agent 1's publication code.

No emulator, Docker container, Android/SDK build, device/server/transport trial or
image-library suite ran. No file durability, atomic apply/migration, stale-review
transaction, cleanup activation, Android compatibility or ATAK behavior is proven
by byte-codec tests. Those remain separate work before any writer/rollout.
